# ЛР 2 – обоснование актуальности ВКР

**Тема ВКР:** Методика сравнительной оценки подходов к управлению состоянием в одностраничных веб-приложениях на основе факторного анализа качества логических цепочек

**Автор:** Филатов Арсений Сергеевич

В работе сравниваются подходы к управлению состоянием в одностраничных веб-приложениях: однонаправленный поток, реактивные зависимости, минимальное хранилище, событийный граф и диаграммы состояний. Предмет сравнения – качество логической цепочки, путь от события через обработчик и мутацию состояния к побочному эффекту и реакции интерфейса. Факторный анализ собирает признаки этого качества в группы, и по группам подходы сопоставляются друг с другом.

### Выводы по обзору

В методику входят пять линий. Диаграммы состояний и автоматное программирование задают явную модель поведения (Харел, 1987; Поликарпова, Шалыто, 2009). У реактивного программирования остаются граф зависимостей и неявный порядок обновлений (Байномугиша и др., 2013; Цуканова, Забродин, 2026). Запись и повторное проигрывание проверяют воспроизводимость на вебе (Миккенс и др., 2010; Бург и др., 2013). Прозрачность опирается на связи трассируемости (Джавед, Цдун, 2014). Несколько групп признаков, без свертки в один балл, показывает факторный анализ (Ханебутте и др., 2003). Число факторов сверяется параллельным анализом Хорна (1965).

По этим линиям уже сделано следующее. Библиотеки интерфейса, включая Redux, MobX и Effector, описаны в обзоре (Антонов и др., 2024). Redux, MobX и React Context сравнены по набору критериев на двух приложениях (Мелихова и др., 2023). Для веб-интерфейса BI построена методика с взвешенным индексом производительности (Дегтярев, Государев, 2026). Для логической цепочки в SPA заданы определения, восемь критериев со шкалой 0–3 и стенд на четырех реализациях; на 240 наблюдениях получены три фактора и 77,4 % дисперсии (Филатов, 2026).

Этого недостаточно для сравнительной оценки качества цепочки. Обзор и сравнение на двух приложениях не показывают, где в подходе заданы событие, мутация, эффект и реакция интерфейса, и не считают признаки по явным правилам. Индекс производительности собирает скорость в один балл. В матрице рукописи первый фактор связан с меткой дефектного варианта, третья компонента равна 1,262 и близка к порогу Кайзера, наблюдения не независимы, порядковые шкалы обработаны как числа.

## 3. Обзор и сравнение аналогов

### Прямые аналоги

Прямой аналог решает ту же задачу: сопоставить подходы к управлению состоянием в клиентском приложении.

Мелихова К. А., Томилин Е. С., Кропотов А. С. сравнивают Redux, MobX и React Context (React Hooks) на двух React-приложениях разной сложности. Работа опубликована в трудах XII Конгресса молодых ученых Университета ИТМО (2023, с. 395–402, EDN: QOOQCE). Это сравнение средств управления состоянием, ближайшее по объекту. Ограничение: нет определений логической цепочки, прозрачности и детерминизма, нет шкалы с явными правилами расчета, нет факторной структуры и открытой матрицы наблюдений.

По этой теме я написал рукопись «Факторный анализ прозрачности и детерминизма логических цепочек в SPA». 03.10.2026 она направлена в «Вестник Дагестанского государственного технического университета. Технические науки». В сентябре 2026 по ее мотивам я выступил с докладом на митапе PiterJS. На стенде Redux Toolkit, MobX, Zustand и Effector: 15 сценариев, 4 варианта, 240 наблюдений, три фактора при 77,4 % дисперсии. Данные и скрипты: https://github.com/xWxfFle/ui-state-determinism.

### Косвенные аналоги

Антонов С. А., Вуколов А. А., Кононыхина К. А. дают обзор библиотек интерфейса, включая Redux, Redux Toolkit, Effector и MobX (Вестник науки, 2024, т. 5, № 9, с. 477–504; https://cyberleninka.ru/article/n/obzor-sovremennyh-bibliotek-dlya-razrabotki-interfeysa-veb-prilozheniya). Объект тот же, задача другая: описать инструменты. Измерений цепочек нет, выбор остается качественным.

Дегтярев М. А., Государев И. Б. построили методику сравнительной оценки технологий виртуализации таблиц для веб-интерфейсов BI (Вестник ДГТУ. Технические науки, 2026, т. 53, № 2, с. 61–68, https://doi.org/10.21822/2073-6185-2026-53-2-61-68). Это ближайшая по жанру методика сравнения клиентских технологий. Предмет другой: производительность. Итог – взвешенный индекс и ранжирование. Веса задаются экспертно, свертка не показывает вклад отдельного свойства.

Mugshot (Mickens, Elson, Howell, NSDI '10) и Timelapse / Dolos (Burg и др., UIST '13, https://doi.org/10.1145/2501988.2502050) дают запись и повторное проигрывание исполнения для проверки детерминизма. Сравнения подходов к управлению состоянием в этих работах нет.

Hanebutte N., Taylor C. S., Dumke R. R. (Empirical Software Engineering, 2003, https://doi.org/10.1023/A:1021716832057) показывают факторный анализ в измерении программ. Предметной области SPA там нет. Для ВКР это источник процедуры, вместе с тестом Хорна (Psychometrika, 1965, https://doi.org/10.1007/BF02289447).

### Актуальность исследования

Одностраничные приложения держат логику представления на клиенте, и путь от события до реакции интерфейса проходит через модель состояния. Этот путь сравнивают по API, производительности и объему шаблонного кода. Для веб-интерфейсов уже есть методика, которая сводит метрики производительности во взвешенный индекс и ранжирует технологии (Дегтярев, Государев, 2026). Качество самой цепочки при таком сравнении не измеряется.

Отдельные основания для такой методики уже есть: явные состояния и переходы, реактивный граф, запись и повтор исполнения, связи трассируемости, факторный анализ в измерении программ (источники 1–9). В оценку подходов к управлению состоянием SPA они не собраны. На стенде из 240 наблюдений получены три фактора при 77,4 % дисперсии (Филатов, 2026): свойства цепочки не сводятся к одному баллу, отдельно выделяются объем реализации и длина цепочки. Первый фактор этой матрицы связан с меткой варианта, третья компонента (1,262) стоит у порога отбора. Подходы при этом по-прежнему выбирают по API и замерам скорости, хотя матрица и правила расчета открыты.

### Цель исследования

Разработать методику сравнительной оценки подходов к управлению состоянием в одностраничных веб-приложениях на основе факторного анализа качества логических цепочек и показать, как по полному профилю качества читать различие подходов.

### Задачи исследования

1. Разобрать однонаправленный поток (Flux, Redux), реактивные зависимости (MobX), минимальное хранилище (Zustand), событийный граф (Effector) и диаграммы состояний по устройству цепочки: где заданы событие, мутация, эффект и реакция интерфейса.
2. Зафиксировать, какие из этих различий не видны при сравнении по API и производительности.
3. Определить логическую цепочку и признаки ее качества. Задать шкалы и правила расчета, которые не читают метку варианта `defect`. Результат сравнения – факторный профиль.
4. Пересчитать матрицу этими правилами на стенде из четырех реализаций. Проверить структуру анализом главных компонент и разведочным факторным анализом. Число факторов сверить анализом Хорна. Для шкал 0–3 сопоставить решение с порядковым факторным анализом.
5. Прочитать профили четырех реализаций на эталонном сценарии: поиск, черновик, сохранение, уход со страницы. Рейтинг библиотек не строится.
6. Оставить в открытом репозитории стенда правила расчета, матрицу и границы методики.

### Датасеты и сервисы

Стороннего открытого набора трасс логических цепочек SPA нет. Документация библиотек (Flux, Redux, MobX, Zustand, Effector, XState) задает инженерные соглашения и в список данных не входит.

Собственный стенд открыт: https://github.com/xWxfFle/ui-state-determinism. Исходная матрица – `data/raw-observations.csv`, 240 строк вида «библиотека × сценарий × вариант». Рядом лежат корреляции, MSA, KMO, критерий Бартлетта, собственные значения, факторные нагрузки и проверка устойчивости. Сбор – `npm run collect`. Статистический анализ – `npm run analyze`. Правила расчета – `src/shared/metrics.ts`.

В ВКР матрица пересчитывается по правилам без метки варианта. По тем же сценариям читаются профили реализаций. Новый внешний сервис для этого не требуется.
